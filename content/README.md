# 콘텐츠 수정

`portfolio.json`은 프론트엔드의 정적 페이지와 PostgreSQL 초기 데이터의 공통 원본입니다.

- `profile`: 이름·소개·GitHub·관심 분야·실제 사용 기술. 숙련도나 경력을 추정해 적지 않습니다.
- `projects`: 확인된 프로젝트만 추가합니다. `slug`에 맞는 상세 페이지도 작성하세요.
- `projects[].contributions`: 프로젝트 안에서 AI를 활용한 작업(`aiAssisted`)과 직접 설계·구현·수정·검증한 작업(`handsOn`)을 구분합니다. 각 항목은 `title`, `description`, 선택적인 `evidenceUrl`로 구성합니다. 두 목록에 같은 기능을 적어도 되며, 설명에는 해당 기능에서 각자 맡은 범위를 구체적으로 적습니다. 코드가 존재하거나 커밋 작성자가 본인이라는 이유만으로 손 코딩으로 분류하지 않습니다. 확인된 제작 범위가 없으면 빈 배열을 유지하고, 화면에는 정리 중 상태를 표시합니다. 임의 비율이나 기여도를 넣지 않습니다.
- `posts`: 실제 글이 확인되면 `title`, ISO 날짜 `date`, 문자열 배열 `tags`, 기존 주소 `url`을 넣습니다. 주소를 바꾸지 않습니다.

현재 저장소는 CRA 빌드 결과물만 포함했고, 소스맵에서 이름 김유림을 확인했습니다. 현재 역할은 사용자가 직접 확인한 풀스택 개발자로 반영했습니다. 글·날짜·태그·이메일은 발견되지 않아 비워 두었습니다. 기존 결과물과 정적 파일은 보존했고 `/legacy/`에서 이전 소개 페이지를 열 수 있습니다.

ryu-deco의 기술과 구현 설명은 인접한 별도 저장소 `../ryu-deco`의 README, package.json, 렌더러·내보내기·자동 저장 코드를 읽어 확인했습니다. 별도 저장소의 파일은 수정하지 않았습니다.

데이터를 수정한 뒤 `npm run build`를 실행해 정적 사이트를 갱신하세요. API를 사용하는 경우 `npm run db:seed`로 DB에도 반영합니다. API는 공개된 포트폴리오 데이터를 읽기 전용으로 제공하며 웹에서 DB 내용을 편집하는 기능은 없습니다.
